## Корневая причина

### Конвертер EDT форм не трансформирует структуру XML

**Что делает наш конвертер** (`scripts/edt_to_1c_platform.ps1`):
```
EDT Form.form (NS: http://g5.1c.ru/v8/dt/form)
     ↓ только замена namespace
Platform Form.xml (NS: http://v8.1c.ru/8.3/xcf/logform) — но структура EDT!
```

**Проблема:** EDT и платформенный формат форм — **принципиально разные XML-структуры**:

| EDT формат | Платформенный формат |
|-----------|---------------------|
| `<items xsi:type="form:FormGroup" name="...">` | `<UsualGroup name="..." id="...">` |
| `<items xsi:type="form:HTMLDocumentField" ...>` | `<HTMLDocumentField name="..." id="...">` |
| Вложенность через `<items>` | Вложенность через `<ChildItems>` |
| Без числовых `id` | Каждый элемент с уникальным `id` |

**Результат:** 1C принял XML (EDT-структура с платформенным NS), но проигнорировал неизвестные элементы — форма оказалась пустой:

```xml
<!-- Фактический Form.xml в базе после загрузки: -->
<Form xmlns="http://v8.1c.ru/8.3/xcf/logform" ...>
    <AutoCommandBar name="" id="-1"/>
    <Attributes/>
</Form>
```

**Цепочка сбоя:**
1. Форма загружена пустой (без элементов)
2. BSL-код в `ПриОткрытии` обращается к `Элементы.РедакторЗапроса.УстановитьТекст(...)`
3. Элемент не существует → необработанное исключение
4. 1C показывает диалог «К сожалению, возникла непредвиденная ситуация»

## Что нужно исправить

### Вариант 1 (рекомендуемый): Установить 1C:EDT + ring

```bash
ring edt@2025.2.0 workspace export \
  --workspace /tmp/ws \
  --project 1CDeveloperToolkit \
  --configuration /tmp/xml_export
```

Skill `edt-to-configurator.js` поддерживает этот путь — при наличии `ring` он используется автоматически.

### Вариант 2: Реализовать полный XML-трансформер EDT→платформа

Требует реализации маппинга:
- `form:FormGroup` → `UsualGroup` с атрибутом `id`
- `form:HTMLDocumentField` → `HTMLDocumentField`
- `form:Table` → `Table` с `ChildItems`
- Атрибуты форм из `<attributes>` → платформенный формат
- Генерация уникальных числовых `id` для каждого элемента

### Вариант 3 (быстрый): Сохранить формы в nopik и использовать их

Формы в `C:\bases\nopik` уже правильные (созданы вручную в EDT и загружены через конфигуратор). Можно выгрузить правильный XML из nopik и использовать его как эталон.
