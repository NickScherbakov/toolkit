# Improvements register

Ниже перечислены улучшения, которые удалось сформулировать по текущему содержимому репозитория (`README.md`, `auto_install.md`, `ПраваДоступа.md`, `РасширениеАнализаФорм.md`, `ИспользуемыеБиблиотекиИСервисы.md`, `СправочныеМатериалы.md`, `Документация.docx`, issue templates).

## High

1. **Сделать каталог инструментов единым источником истины.**  
   Обоснование: перечень инструментов, ссылки и роли описаны в нескольких местах и легко расходятся при ручном обновлении.
2. **Явно документировать отсутствие публичных исходников как критический блокер.**  
   Обоснование: README уже сообщает, что исходники не хранятся в репозитории, но задача на продуктовые изменения без этой оговорки вводит в заблуждение.
3. **Добавить CI-проверки для структуры документации и каталога.**  
   Обоснование: в репозитории нет пользовательского CI, поэтому даже простые ошибки в ссылках/структуре остаются незамеченными.

## Medium

1. **Усилить triage issues полями приоритета, влияния и артефактов.**  
   Обоснование: существующие шаблоны не собирают severity, expected impact и ссылки на приложенные логи.
2. **Выделить migration/upgrade инструкции в самостоятельные документы.**  
   Обоснование: установка, обновление, пакетный запуск и ограничения по правам разбросаны по нескольким файлам и бинарной документации.
3. **Расширить документацию по безопасности и внешним зависимостям.**  
   Обоснование: текущий список сервисов очень краткий и не объясняет риски, ограничения и способы безопасного обновления.

## Low

1. **Постепенно заменить docx/pdf markdown-эквивалентами.**  
   Обоснование: бинарные файлы плохо подходят для code review, diff и автоматизации.
2. **Нормализовать терминологию и язык описаний.**  
   Обоснование: часть материалов использует разные названия для одних и тех же возможностей, что ухудшает UX публичной документации.
