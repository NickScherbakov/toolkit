# Migration plan

## Objective

Перевести публичный репозиторий Toolkit от ручного сопровождения списков и разрозненных документов к проверяемому каталогу и повторяемому quality-gate.

## Steps

1. **Зафиксировать текущий публичный срез.**  
   Добавить `data/toolkit_catalog.json` как снимок перечня инструментов, ссылок и блокеров.
2. **Включить автоматические проверки.**  
   Запускать validate/test pipeline в каждом PR и на push в `master`.
3. **Свести изменения документации к обновлению каталога и целевых markdown.**  
   Любое добавление инструмента, роли или критического ограничения сначала отражать в каталоге.
4. **Переносить сведения из бинарной документации в markdown по частям.**  
   Начинать с установочных и миграционных материалов.
5. **Подготовить переход к приватному продуктовику.**  
   После получения доступа к закрытым исходникам переиспользовать backlog и design doc для настоящей реализации продукта.

## Backward compatibility

- README, существующие ссылки и issue templates остаются на месте.
- Новый каталог является дополняющим артефактом и не ломает текущий пользовательский сценарий.

## Risks

1. Каталог может устареть, если его не обновлять вместе с README.
2. Без доступа к приватным исходникам migration plan покрывает только публичную оболочку репозитория.

## Mitigations

1. CI блокирует расхождение README и каталога.
2. Критический блокер вынесен отдельно, чтобы не смешивать документационный PoC с продуктовой реализацией.
